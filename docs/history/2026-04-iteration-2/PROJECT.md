# Cerberus 技术方案

> 你的秘密、记忆与最后的话，在本地得到守护。

_当前阶段：Iteration 2 / 数据安全与可迁移_
_最后更新：2026-03-31_

## 1. 当前状态

Cerberus 已完成第一期 MVP，当前仓库已经具备以下能力：

- 本地初始化金库
- 主密码解锁与短时会话
- 新建 / 查看 / 列表 / 编辑 / 删除文本条目
- 分类与标签管理
- 标题与标签搜索
- 加密附件保存与导出
- 基础 OpenClaw Skill 接入
- `--vault` / `--home` 路径覆盖
- `init` / `unlock` 的非 TTY 脚本输入

本阶段不再以“能不能做出 MVP”为目标，而是进入“是否可恢复、可迁移、可自动化使用”的增强阶段。

## 2. Iteration 2 目标

第二期聚焦以下目标：

- 备份与恢复链路
- 明文导出链路
- CLI 自动化体验补齐
- Skill 最小闭环补齐

本期希望交付一个“即使设备迁移或数据整理，也不容易卡住用户”的版本。

## 3. 本期范围

### 3.1 计划纳入

| 模块 | 功能 | 说明 |
|---|---|---|
| 备份 | `backup create` | 生成可校验的本地备份包 |
| 备份 | `backup verify` | 校验备份结构与完整性 |
| 导出 | `export --all` | 明文导出全部条目 |
| 导出 | `export --category` | 导出指定分类 |
| 导出 | `export --format` | 支持 `json` / `markdown` |
| 会话 | `lock` | 主动清理当前会话 |
| CLI 输出 | `--json` | 为 `list/search/show` 提供结构化输出 |
| Skill | 补齐最小意图 | 支持 `delete/edit/attach` 的基础映射 |

### 3.2 暂不纳入

- 语义搜索
- TUI
- 多端同步
- 时间线视图
- Shamir 分片恢复
- 时间锁

## 4. 产品原则

### 4.1 继续坚持的原则

- 加密优先于便利
- 默认离线
- 元数据最小暴露
- 尽量使用成熟组件，不自造密码学方案
- 可自动化，但不牺牲默认安全边界

### 4.2 Iteration 2 新增原则

- 可恢复性优先于新奇功能
- 所有“导出明文”操作都要明确、可预期
- 脚本模式与交互模式应行为清晰，不混淆
- 备份与导出都要尽量可验证、可测试

## 6. Iteration 2 设计方向

### 6.1 备份

目标：

- 对整个 vault 做一致性备份
- 备份结果可校验
- 不要求依赖外部服务

建议包含：

- `db.sqlite`
- `config.json`
- `keys/identity.age.enc`
- `vault/entries/**`
- `vault/attachments/**`

建议增加：

- `manifest.json`
- 文件列表与大小
- 哈希摘要
- 备份创建时间
- 格式版本

### 6.2 导出

目标：

- 允许用户将明文条目导出到指定目录
- 支持分类过滤
- 支持 `json` 与 `markdown`

边界：

- 导出是明确的明文行为
- 不自动删除用户指定输出目录
- 不默认覆盖已有文件

### 6.3 CLI 自动化

本期应进一步补齐：

- `lock`
- `--json`
- 更稳定的非交互输入
- 更明确的错误码与脚本返回语义

### 6.4 Skill 补齐

目标不是做复杂 agent，而是补齐最基础命令映射：

- `delete`
- `edit`
- `attach add`
- `attach list`
- `attach export`

## 7. 风险与取舍

### 7.1 明文导出风险

导出本身就是主动暴露明文，因此本期只做：

- 明确命令触发
- 明确输出位置
- 明确格式

不做：

- 隐式自动清理
- 不可见的临时导出

### 7.2 备份格式风险

如果一开始就追求复杂的加密备份包格式，容易拉高实现复杂度。本期建议先以“结构清晰、可校验、可恢复”为第一目标。

### 7.3 Skill 边界

Skill 只做命令映射，不在本期引入复杂的对话推理状态机。

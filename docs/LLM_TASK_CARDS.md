# Cerberus Iteration 4 任务卡

_最后更新：2026-04-05_

## 用途

本文件用于将 Cerberus 第四期迭代拆成更适合分发给不同 LLM 的任务卡。

本期主题：

- CLI 契约稳定
- 错误与退出语义
- 高风险操作追溯
- 端到端演练可信度

## 使用方式

每次下发任务建议附带：

1. 当前技术方案：`docs/PROJECT.md`
2. 当前迭代计划：`docs/ITERATION_PLAN.md`
3. 本文档中对应任务卡
4. 仓库当前代码状态

## 推荐分发策略

本期仍然适合拆卡，而不是整期一次性交给单个模型：

1. 用更稳的模型做 maintenance `--json`
   建议：`gpt-5.4`。
2. 用擅长系统梳理的模型做错误与退出码整理
   建议：`gpt-5.3-codex`。
3. 用较稳妥的模型做操作日志
   建议：`gpt-5.4-mini` 或 `gpt-5.3-codex`。
4. 用更强的模型做端到端演练和验收
   建议：`gpt-5.4`。

本期重点不在 UI，而在“是否适合 agents 长期调用”，因此比较模型时，建议优先看“契约稳定性、失败语义、日志边界、测试可信度”。

## 任务卡列表

### Task Card 1：维护命令 JSON 契约

适合模型：

- `gpt-5.4`
- `gpt-5.3-codex`

```md
# Task Card 1：维护命令 JSON 契约

## 目标

请补齐关键维护命令的 `--json` 输出。

## 本次范围

- `backup verify --json`
- `backup restore --dry-run --json`
- `import --json`
- `doctor cleanup --json`

## 不在范围内

- 不改动底层业务语义
- 不为了 JSON 输出移除现有文本输出
- 不扩展到所有命令

## 可修改文件范围

- `src/commands/**`
- `src/services/**`
- `src/cli/index.ts`
- `tests/**`
- `README.md`

## 实现要求

- JSON 字段命名稳定
- 文本输出与 JSON 输出结论一致
- 对失败场景也考虑机器可读性

## 验收标准

- 关键维护命令可被脚本稳定消费
- JSON 输出结构有测试覆盖
```

### Task Card 2：错误与退出码整理

适合模型：

- `gpt-5.3-codex`
- `gpt-5.4-mini`

```md
# Task Card 2：错误与退出码整理

## 目标

请梳理并补强关键维护命令的错误分类和退出语义。

## 本次范围

- 参数错误
- vault 状态错误
- 校验失败
- 恢复/导入/cleanup 的高风险失败路径

## 不在范围内

- 不重构整个错误体系
- 不引入远程错误上报

## 可修改文件范围

- `src/core/errors.ts`
- `src/commands/**`
- `src/services/**`
- `tests/**`
- `README.md`

## 实现要求

- 失败类型应尽量能被脚本区分
- 不泄漏敏感内容
- help / README / 测试要同步

## 验收标准

- 常见失败路径具有明确退出语义
- 脚本不必依赖脆弱文本判断错误类别
```

### Task Card 3：高风险操作日志

适合模型：

- `gpt-5.4-mini`
- `gpt-5.3-codex`

```md
# Task Card 3：高风险操作日志

## 目标

请为关键维护命令提供最小必要的本地操作日志。

## 本次范围

- `backup create`
- `backup restore`
- `import`
- `doctor cleanup`

## 不在范围内

- 不记录正文或附件明文
- 不做远程上报
- 不做复杂查询界面

## 可修改文件范围

- `src/services/**`
- `src/core/**`
- `tests/**`
- `README.md`

## 实现要求

- 只记录操作摘要
- 保持默认保守
- 日志格式应便于后续查询扩展

## 验收标准

- 日志足以复盘关键操作
- 日志不泄漏敏感内容
```

### Task Card 4：端到端演练与验收

适合模型：

- `gpt-5.4`
- `gpt-5.3-codex`

```md
# Task Card 4：端到端演练与验收

## 目标

请补齐关键维护链路的集成演练和发布验收文档。

## 本次范围

- 备份 -> 校验 -> 恢复 -> 解锁 -> list
- 导出 -> 导入 -> 再导出
- doctor / cleanup 的保守边界回归

## 不在范围内

- 不做 UI 演示
- 不引入云端环境依赖

## 可修改文件范围

- `tests/**`
- `README.md`
- `docs/**`

## 实现要求

- 优先覆盖最关键链路
- 真实反映当前支持范围
- 不写超出当前实现能力的宣传性文档

## 验收标准

- 至少一条恢复主链路可重复验证
- 至少一条导入回环可重复验证
- cleanup 的高风险边界有回归测试
```
